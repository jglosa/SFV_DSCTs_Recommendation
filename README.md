# SFV 통제 선호 유도 도구 — 데모 (v0.3)

인터랙션은 진짜, 지능은 가짜.

**구조의 핵심:** 설문 전체가 하나의 `scroll-snap` 피드다. 질문 카드와 영상 카드가 같은
스크롤 면에 섞여 있고, 답하면 **아래에 다음 카드가 생긴다**. 위로 밀어서 넘어간다.
"다음" 버튼은 없다.

아직 답하지 않은 질문 아래에는 카드가 존재하지 않으므로 그냥 넘길 수 없다.
스크롤을 막는 방식이 아니라, 넘길 대상이 아직 없는 방식이다.

---

## 1. 실행

Node.js 18 이상.

```bash
cd sfv-elicit-demo
npm install
npm run dev
```

주소가 두 개 뜬다.

```
➜  Local:   http://localhost:5173/
➜  Network: http://192.168.0.xx:5173/
```

- **노트북** → `Local`. 휴대폰 프레임 + 오른쪽 실시간 모니터 패널.
- **휴대폰** → 노트북과 **같은 wifi**에 연결한 뒤 `Network` 주소 입력. 전체화면으로
  뜨고 모니터 패널은 자동으로 숨는다.

멈추려면 `Ctrl+C`.

### 휴대폰에서 앱처럼 띄우기

iOS Safari → 공유 → "홈 화면에 추가". Android Chrome → 메뉴 → "홈 화면에 추가".
주소창이 사라져서 실제 앱과 훨씬 비슷해진다. 참가자 세션은 이 방식이 맞다.

## 2. 카드 흐름 (총 28장)

System Questions Flow 기준.

| 단계 | 내용 | 조작 |
|---|---|---|
| — | 인트로 | 시작 버튼 → swipe |
| **S0** | SFV 사용 환경 — 기기 / 경로 / 플랫폼 | 복수 선택, **기타 → 주관식 입력** |
| **S1** | 통제 범위 | **모의 앱 UI에서 요소를 직접 탭** |
| **S2** | 통제 규칙 (Scheduling) | **원형 24시간 시계**, 탭·드래그 |
| **S3** | 개입 시점 | 적응 스크롤 3장 → 상황 설명 + 체험 ×3 → 순위 |
| **S4** | 개입 강도 | 카드 한 장 = 판단 한 번, 좌우 swipe로 이분 탐색 |
| **S5** | 우회·임시해제 | 시나리오 4개, yes/no |
| — | 결과 | 아키타입 · 프로필 · 추천 · 보호층 · 한계 · 판정 근거 |

### S1 — 모의 UI에서 직접 고르기

두 화면이 나오고, 점선으로 표시된 실제 UI 요소를 누른다.

- **홈 피드** — 앱 로고(`app`) / Shorts 선반(`entry-point`) / 하단 Shorts 탭(`app-tab`)
- **Shorts 플레이어** — 채널명(`creator`) / 해시태그(`content-category` → 카테고리 시트)

id는 capability 매트릭스의 `scope_levels` 값과 1:1 대응한다.
숏폼 화면은 선택이 필수가 아니므로 그냥 위로 밀어 넘길 수 있다.

### S2 — 원형 24시간 시계

1~24시. **0시는 없다.** 24시가 위(자정), 12시가 아래(정오)인 표준 24시간 다이얼.
19~6시는 배경이 어둡게 처리되어 밤 시간대가 구분된다. 선택 구간은 순환으로 묶여
`22–2시` 형태로 표시된다.

### S3 — 시점별로 맞는 화면에서 개입이 발생

각 시점은 그 의미에 맞는 화면 위에서 뜬다.

- **Pre** — 휴대폰 홈 화면(앱 아이콘 격자). MyTube만 활성이고 나머지는 흐림 +
  클릭 차단. 누르면 "여는 중…" 후 개입
- **At** — MyTube 홈. 하단 Shorts 탭만 유도 표시되고 그것을 누를 때
- **InUse** — 이미 보고 있는 영상 위, 3.2초 후

**설명과 라벨을 분리했다.** 체험 전 카드에는 *어느 화면에 있고 무엇을 하려는지*까지만
쓴다. 개입의 정체는 미리 말하지 않는다 — 미리 말하면 체험이 아니라 설명을 평가하게
되므로. 대신 개입이 뜬 뒤 오버레이의 `이 개입은 —` 줄에서 무엇을 잡아내는
개입인지 설명한다.

**되짚기는 번호로.** 설명 카드에 ①②③, 개입 배지에 `① 진입 전 개입`, 순위 카드의
각 항목에도 겪은 순서 번호가 붙는다. 제시 순서가 무작위여도 매핑이 된다.

제시 순서는 현재 무작위. 실제 수집 때는 참가자 번호 기반 완전 카운터밸런싱으로
바꿀 것 (6개 순열 × n≈50 → 순열당 8명).

## 3. 실시간 모니터 패널 (노트북에서만)

- **현재 위치** — 지금 몇 번째, 어느 단계, 어느 카드인지
- **카드 목록** — 단계별로 묶인 전체 목록. **아무 카드나 클릭해서 이동**
- **입력 현황** — S0~S5 각 단계의 입력값이 실시간 반영.
  범위 / 시간대 / 제시 순서 / 선호 순위 / 강도 탐색 로그(`4○ → 6○ → 7✕`) /
  반전 검증 / 우회 4개 각각의 답
- **응답 프리셋 주입** — 세 조합. 결과 카드에서 바꿔가며 비교하는 용도
  - 경계 설계자형 — 진입 전 선호, 강도 7, 우회 전부 차단
  - 문턱 관리자형 — 진입 시점 선호, 강도 4
  - 사후 성찰가형 — 사용 중 선호, 강도 2, 반전 검증 실패 + 기타 주관식 사례

### 기기 간 동기화는 안 된다

참가자가 자기 휴대폰으로 접속하면 별개의 브라우저 세션이므로 노트북 패널에
반영되지 않는다. 기기 간 동기화는 서버(웹소켓)가 필요하고, 데이터 저장을 붙일 때
같이 하는 것이 맞다.

실제 세션에서 참가자 휴대폰을 써야 한다면 **화면 미러링**(Android: scrcpy,
iOS: QuickTime / AirPlay)이 서버 없이 되는 가장 현실적인 방법이다.
데모라면 노트북에서 폰 프레임을 직접 조작하는 편이 낫다.

## 4. 설계 결정 다섯 가지

**강도 탐색은 이분 탐색이다.** multi-armed bandit이 아니다. 사다리는 taxonomy 안에서
이미 단조 정렬되어 있으므로 순서가 있는 공간이고, 순서가 있으면 학습이 아니라 탐색으로
최적점을 찾을 수 있다. 8단계면 3회로 수렴한다. 수렴 후 같은 단계를 다시 물어
일관성을 검증하고, 답이 뒤집히면 임계값이 불안정하다고 기록한다.
(검증 예: 4 수용 → 6 수용 → 7 과함 → 6 확정 → 반전 확인)

**사다리는 시점에 종속된다.** S3의 1순위를 받아 S4의 사다리를 고른다. 진입 시점의
3초와 사용 중의 3초는 심리적으로 다른 개입이다. `src/data/features.js`의 `LADDERS`.

**Continuous는 4번째 시점 컬럼이 아니다.** 설정 위에 얹히는 보호층이고, S5에서
"막혀야 한다"고 답한 우회 경로에서만 도출된다. 우회 방지 기능이 **존재하는** 경로만
질문한다 — 막을 수단이 없는 우회는 물어봐도 제안할 기능이 없으므로.

**지원되지 않는 범위도 선택할 수 있게 열어둔다.** 콘텐츠 카테고리를 고르면 그 자리에서
지원이 얇다고 알리고, 결과에서 대안과 함께 무엇이 빠지는지 보고한다. 선택을 막으면
"몇 %의 참가자가 시장에 없는 통제를 원했는가"라는 데이터를 스스로 버리는 셈이다.

**체험 전에는 상황만, 체험 후에 이름을.** 개입의 정체를 미리 설명하면 참가자가
경험이 아니라 설명을 평가한다. 순서를 뒤집어야 체험이 오염되지 않는다.

## 7. 아직 안 만든 것

의도적으로 뺐다. 매트릭스 확정 후에 붙이는 게 맞다.

- 백엔드·계정·데이터 저장 (`log[]`은 메모리에만 쌓인다)
- 실제 영상 (그라디언트 카드로 대체)
- 사전·사후 자유서술 설문 — 사용 시간·초과 정도 문항이 필요하다면 여기로
- 완전 카운터밸런싱 (지금은 무작위)
- 결과 화면의 미세 조정 토글
- 기기 간 실시간 동기화

## 8. 확인된 것 / 확인 못 한 것

**로직은 프로그램으로 끝까지 통과시켜 확인했다.** 28장 카드가 순서대로 생성되고,
이분 탐색이 3회+검증 1회로 수렴하며, 21개 점검 항목(기타 주관식 저장, 시계 조각 24개 /
0시 부재, 탭 타겟 수, 카테고리 시트와 경고, 개입 배지 번호, 순위 카드 되짚기 번호,
모니터 패널 항목 등)이 전부 통과했다.

그 과정에서 **막히는 버그 하나를 잡았다.** 숏폼 화면 범위 카드는 선택이 필수가 아닌데
아무것도 고르지 않으면 다음 카드가 생성되지 않아 진행이 멈췄다. 지금은 마운트 시
다음 카드를 미리 만든다.

**시각적 확인은 못 했다.** 컨테이너에 브라우저를 설치할 수 없는 환경이었다.
특히 원형 시계의 라벨 크기와 조각 터치 영역, 모의 유튜브 UI의 비율은 실제로
만져봐야 안다. 어긋나는 곳을 알려주면 고치겠다.
